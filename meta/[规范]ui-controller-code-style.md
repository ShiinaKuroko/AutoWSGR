# UI Controller 页面模块规范

本规范用于 `application/ui/controller` 下的页面控制器模块。它继承
`[规范]navigation-code-style.md` 的文件说明、注释、函数 docstring、依赖边界和
验证要求；两者冲突时以更具体的页面模块规则为准。规范描述职责和代码编排，
不改变页面业务契约。

## 1. 页面模块目录

一个页面或页面组使用 `xx_page/` 作为模块目录：

```text
xx_page/
├── __init__.py
├── constants.py
├── page.py
└── recognition.py       # 只有页面确实拥有 OCR 规则时才创建
```

### `__init__.py`

- 只导出页面模块的稳定公共入口，例如 `XxPage`、页面目标枚举和必要的数据类型。
- 不执行页面注册、设备操作、OCR 初始化或其他导入副作用。
- 兼容旧导入路径时，通过包级导出保持调用方入口，不在其中复制实现。

### `constants.py`

- 只保存当前页面私有的物理校准：点击坐标、滑动坐标、按钮颜色、像素阈值和
  页面专用视觉参数。
- 页面专用校准不得继续放在 `common.calibration`、通用类型枚举或其他页面模块中。
- 不保存 `GameContext`、设备对象、可变运行状态、调度规则、业务结果或 retry 状态。
- 每个页面常量都必须带业务语义注释，说明“点击/检测的对象和所在状态”，不只写
  坐标或变量名。
- 坐标使用归一化相对值，格式统一为 `0.xxxx`；不得在页面代码中混用 1280x720
  绝对像素或未经说明的坐标换算。
- 颜色常量必须注明颜色用途和容差；时间和阈值必须注明它影响的页面动作或失败边界。
- 只有真实被页面使用的常量才保留；不为未来页面预留空映射、Factory 或 Registry。

示例：

```python
CLICK_BACK = (0.0219, 0.0583)  # 页面左上角返回按钮，用于离开当前页面。
CLICK_CONFIRM = (0.8898, 0.8903)  # 建造资源确认按钮，用于提交当前建造配方。
```

### `page.py`

- 只定义页面内 UI 行为：页面检查、可见状态读取、点击、打开/关闭面板、等待
  页面结果和页面级回退。
- 可以调用 `common.vision`、`common.ui.interaction`、`constants.py` 和本模块的
  `recognition.py`；不得复制 OCR、坐标加载器或其他页面的实现。
- 不负责跨任务调度、业务状态持久化、设备初始化或创建新的运行时上下文。
- 页面识别属于 UI 状态检查，放在 `page.py`；只有 OCR 文本识别和 OCR 规则放在
  `recognition.py`。
- 组合动作必须由页面已有的原子动作组成，并明确成功、失败和终态。

### `recognition.py`

- 只定义当前页面拥有的 OCR 代码：OCR 输入裁剪、文本规则、结果模型、文本解析和
  OCR 失败边界。
- 不定义点击坐标、页面导航、设备操作、页面模板检查或业务调度。
- OCR 引擎必须由调用方注入或从既有上下文取得；不得在识别函数中隐式创建新的
  `OCREngine`。
- 页面没有 OCR 专属逻辑时，不创建空的 `recognition.py`。页面模板匹配不是 OCR，
  应留在 `page.py`。

## 2. 文件级说明

每个 Python 文件首部必须有文件级 docstring，按导航规范写明：

```python
"""模块功能：说明当前文件负责的页面能力。

上层调用：
- 只列直接调用方和调用目的；没有时写 ``- 无``。

下层依赖：
- 只列直接依赖和用途；没有时写 ``- 无``。
"""
```

路径从 `application`、`business`、`common` 等顶层包开始，不重复写
`autowsgr.`。页面模块之间使用绝对导入，遵守仓库禁止相对导入的规则。

## 3. 注释分类

注释类型按 `[规范]navigation-code-style.md` 划分：

- 文件级说明：模块功能、上层调用、下层依赖和必要的边界背景。
- 功能分区：只在文件有多个清晰业务职责时使用，例如“页面检查”“建造操作”“页面回退”。
- 常量注释：解释物理控件、页面状态、参数用途和失败含义；每个页面常量都要有业务语义。
- 行为注释：解释业务规则、设计原因、输入输出、边界条件或兼容约束。
- workaround 注释：必须写触发条件、保留原因、移除条件和对应验证，不能只写“临时处理”。

禁止用大段分隔线装饰短文件，禁止用注释逐行翻译代码，禁止把旧实现历史搬入
当前文件作为无行动价值的背景。

## 4. 函数命名

同一业务语义使用同一前缀；前缀本身表达动作，不混用近义词或拼写变体。

| 前缀 | 语义 | 示例 |
|---|---|---|
| `check_` | 只检查页面或控件状态，不产生副作用 | `check_current_page`、`check_dialog` |
| `read_` | 读取当前画面中的已知状态或结果 | `read_active_tab` |
| `open_` | 打开页面内面板、浮层或选择器 | `open_type_filter` |
| `close_` | 关闭页面内面板或浮层并确认终态 | `close_repair_overlay` |
| `select_` | 选择页面中的选项、标签或菜谱 | `select_recipe` |
| `click_` | 执行一个有明确业务对象的点击动作 | `click_slot`、`click_confirm` |
| `confirm_` | 确认弹窗或不可逆页面操作 | `confirm_force_cook` |
| `cancel_` | 取消弹窗或当前操作 | `cancel_force_cook` |
| `dismiss_` | 关闭提示、动画或非业务弹窗 | `dismiss_popup` |
| `go_back` | 从当前页面回到调用方期望的父页面 | `go_back` |
| `navigate_to` | 在当前页面组内进入明确目标页面 | `navigate_to` |
| `recognize_` / `parse_` | 仅用于 `recognition.py` 中的 OCR 识别和解析 | `recognize_cards` |

页面当前状态统一使用 `check_*`，不再新增同义的 `is_*`、`has_*` 或
`get_*` 作为状态检查。读取状态使用 `read_*`；动作使用对应动作前缀。已有
调用方必须随改名同步更新，不能保留一个只为过渡而没有真实消费者的别名。

## 5. `def` 排序

函数按业务调用链和职责分组，不按字母排序。页面控制器类使用以下默认顺序：

1. `__init__`：保存显式注入的上下文和设备引用。
2. `check_*`：页面和浮层状态检查。
3. `read_*`：读取当前可见页面状态。
4. `open_*` / `close_*`：打开、关闭页面内面板和浮层。
5. `select_*`：选择标签、菜谱、筛选项等页面选项。
6. `click_*` / `confirm_*` / `cancel_*` / `dismiss_*`：原子页面动作。
7. 组合业务动作：按真实页面流程排列，复用前面的原子动作。
8. `go_back` / `navigate_to`：页面级边动作；若调用链要求，可与所属导航组相邻。
9. 私有辅助方法：放在文件末尾，并靠近唯一使用它的功能组；跨组复用时统一放末尾。

实际页面流程优先于机械模板。例如标签页应将“检查当前标签 → 切换标签”保持相邻，
浮层应将“打开 → 操作 → 关闭/确认终态”保持相邻。

## 6. 依赖和状态边界

- `GameContext` 是运行时上下文的唯一所有者；页面控制器只保存并使用调用方注入的
  上下文，不自行创建或刷新上下文。
- 页面专用物理坐标归页面 `constants.py` 所有；通用设备、视觉、交互工具仍归
  `common` 所有。
- `page.py` 不把业务任务调度、跨任务状态或用户配置规则塞入页面动作。
- `recognition.py` 不直接点击设备，也不决定导航或调度。
- 页面之间通过稳定的公共类/方法和导航图调用，不跨模块读取私有常量或内部状态。
- 删除旧公共校准包装前，必须搜索全部导入方；若还有消费者，先迁移消费者再删除。

## 7. 验证和交付

每个页面模块改造后至少执行：

- 目标模块及直接调用方的导入 smoke；
- 受影响 Python 文件的 `compileall`；
- 受影响文件的 `git diff --check`；
- 与行为边界匹配的 focused 验证。pytest 或实机验证未执行时必须如实记录。

交付前还要确认：

- 目标模块没有遗漏旧导入方；
- `constants.py` 中点击坐标均为 `0.xxxx`，且每项有业务语义注释；
- `page.py` 不含 OCR 实现，`recognition.py` 不含 UI 点击或页面导航；
- 函数前缀和顺序符合本规范；
- 删除的旧校准文件没有剩余消费者；
- diff 不包含 `bath_page` 的非 A1 修改、无关模块或生成文件。

## 8. 明确禁止

- 不为了目录形式创建空的 `recognition.py`。
- 不把页面坐标、颜色或 OCR 参数重新放回 `common` 以逃避模块边界。
- 不复制 `bath_page` 或其他页面的识别实现来凑样板。
- 不使用宽泛 `try/except`、静默 fallback 或第二套状态源掩盖页面终态问题。
- 不用 `is_*`、`has_*`、`get_*` 与 `check_*` 混写同一类状态检查。
- 不在本规范落地时顺手重构未列入本批次的页面模块。
