# [架构] 导航器

> 状态：2026-10-12 定稿（对应提交 `cf1955b`）
> 关联：`[任务书]导航器重写.md`｜`[任务书]初始化重写.md` §8｜`[规范]python-code-style.md`｜`[规范]ui-controller-code-style.md`

## 1. 模块功能

把「当前在哪个页面」变成「要去哪个页面」的一次可确认转移：识别当前页 → 算路 → 逐边点击 → 前后识别 → 落栈。

## 2. 分层与职责

| 文件 | 职责 |
| --- | --- |
| `service.py` | 公开入口：算路、编排启动段与浮窗、落栈与回退 |
| `executor.py` | 逐边执行一条算好的路径，并在每跳两端做前后识别 |
| `registry.py` | 页面 → 到达确认、页面 → 可达边、广度算路；`NavTarget` 边类型也在这里 |
| `types.py` | `PageName` 与导航错误；**零依赖**，供下层控制器导入 |
| `page_checker/` | 各页面的识别入口：只读画面事实，不点击、不导航 |

调用方向：`service → executor → registry → page_checker`，点击动作落到 `controller`。

`__init__.py` 不导出实现——包入口若顺带加载 `service`，会与控制器的页面模块形成循环导入，
调用方一律从 `navigation.service` 直接导入 `NavigationService`。

## 3. 一次导航的语义

「点一下」天然成对：旧页面的标志应当消失（后识别），新页面的标志应当出现（前识别）。
执行器同时掌握「离开谁」（压栈前的栈顶）与「去往谁」（边的目标），因此这个判断由它统一负责；
边与 checker 都不各自声明，只提供动作与识别事实。

每跳顺序：边的动作 → 离开确认（后识别）→ 到达前的上层处理 → 到达确认（前识别）→ 压栈。

## 4. 稳定入口

```text
NavigationService(ctx, *, session=None)
  navigate_to(target, **params)   页面到页面；起点即目标时短路；从主页出发先清浮窗
  navigate_back()                 按导航栈回退
  navigate_to_login()             把「处于启动阶段」的游戏带到登录页
```

`registry` 只导出 `get_targets` / `get_checker` / `find_path`。
注册表只维护「能去哪、怎么去、到了吗」，每条边就是一行数据，不为边写转发函数。

## 5. 启动段

`navigate_to_login` 只处理「游戏处在启动阶段」这一段，因为这三个画面没有可导航的边，
也不是导航目标。节奏由游戏特性决定：

| 信号 | 特性 | 处理 |
| --- | --- | --- |
| 健康游戏提示（黑屏） | 宽泛校验，识别不到不重要 | 识别不到 → 等 3 秒看下一项 |
| **更新提示** | **唯一硬分支**：弹出即游戏卡死 | **识别到 → 抛 `ManualUpdateRequiredError`** |
| 加载中 | 宽泛校验 | 识别不到 → 等 3 秒 |
| 登录页 | — | 重试等待 |

**它不拉起 App、不做换区**：拉起 App 与 SL 归 dispatch，换区走导航图的现成边。
已经在某个页面上时，本方法不做任何事（幂等）。

## 6. 浮窗

到达主页、或从主页出发时，`service` 处理每日弹窗：公告与奖励各自独立检测，最多轮询若干轮，
直到某一轮什么都没发现；进程级标记保证每天只跑一次。

它属于「到主页」的内部流程——不能放进换区路径，因为那是另一件事。

## 7. 换区

换区就是两条普通边，没有专属入口：

```text
登录页 → 区服选择页              点开列表
区服选择页 → 登录页(server=名)    点目标区服，列表自动收起
```

**位置由注册表内部现算**：OCR 逐条比对四个区服条目，读不到时按静态映射兜底。
调用方只传区服名，不传位置——dispatch 不做 OCR，也不该知道列表顺序。
「切换大区」按钮（黄底那个）会要求选择 IOS/安卓大区，**本版本不支持，不点它**。

## 8. 错误

| 错误 | 含义 | 调用方应有的反应 |
| --- | --- | --- |
| `NavigationError` | 识别不到页面、离开/到达确认失败 | 恢复：dispatch 走一次 SL 后重来 |
| `ManualUpdateRequiredError` | 游戏需要更新，重启不会改变 | 转成人工处理错误，**不要 SL** |

## 9. 边界

**不做**：页面坐标与校准数据、OCR 参数、业务流程、进程生死（拉起/强杀）、任务恢复决策。

**不依赖**：dispatch 的处理器与任务队列、任何业务域；设备能力只经 `ctx.runtime.ctrl` 的公开入口。

**与 dispatch 的分工**：dispatch 决定何时启动、何时 SL、按配置决定是否换区；导航器负责识别与点击。
因此 dispatch 的代码里不出现任何 checker 调用。
