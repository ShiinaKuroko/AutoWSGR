## 4. login → home 路径设计（用户定稿）

```text
1. dispatch 拉起 APP，等待初始化
   前识别"初始化页面"（健康游戏提示语）→ 识别到马上后识别
2. APP 自动切换页面。每个分支都按"**先后识别、再前识别**"（先确认不存在，再确认存在）：

   分支一 · 检查是否需要更新：
     - 后识别"是否需要更新"（OCR，期望"有新的内容需要更新"）
       后识别通过 = 确认**没有**更新 → 进入分支二
     - 前识别"是否需要更新"
       前识别通过 = 确认**有**更新 → **报错**，交用户手动处理

   分支二 · 检查是否正在加载：
     - 后识别"正在加载"（OCR，期望"正在进入港区"）
       后识别通过 = 加载**已结束** → 直接进入下一步
     - 前识别"正在加载"
       前识别通过 = 仍在加载 → **等 3 秒后再做一次后识别** → 进入下一步
3. 登录页：前识别"区服模板"与"进入游戏模板"，**二选一命中即可**
4. 按用户设置决定是否换区（每天第一次初始化按设置选取；程序保存上下文，
   避免 SL 导致每次都要重选）。可选值：默认 / 胡德 / 俾斯麦 / 昆西 / 长春；
   默认 = 不处理。
   换区流程：点击"点击换区" → 后识别"进入游戏"模板 → 后识别区服四条 OCR
            → 命中目标区服后点击对应条目 → 后识别"切换大区"模板
5. 点击"进入游戏" → 后识别"进入游戏"模板 → 执行主页 checker（导航器）
```

术语映射：前识别 = `expect_*`（识别存在）；后识别 = `expect_*_absent`（识别不存在）。

## 5. 已确认

| # | 结论 |
| --- | --- |
| 1 | 模板命名 `LOGIN_*` / `SERVER_SWITCH_*` 可以 |
