## 四、推荐依赖顺序

### 0. 固定来源基线

1. 等参考 worktree 的未提交稳定性修正形成明确提交，并记录实机结果、失败截图和
   最后正常基线；若仍在实验中，只选取已提交且可复现的代码。
2. 在目标 worktree 重新读取本任务书、两份规范和本计划，确认本次只处理决战升级。
3. 对照目标当前 `decisive_page`、`business.combat.decisive`、资源加载器和导航图，
   建立文件/类/方法映射表；先不删除旧资源或旧兼容入口。

### 1. 资源与地图数据契约

1. 将 `EX-1-1` 至 `EX-6-3` 的节点图结构、`schema_version`、`map_id`、节点标签、
   `next` 边、关键点和敌方舰种代码转换为目标资源格式。
2. 为目标资源加载器增加最小结构校验：文件存在、章节/小关一致、边的目标存在、
   终点唯一、敌方代码属于当前决战允许集合。
3. 用目标 `MapData` 或等价业务查询替代当前 `map_end`/`key_points`/`enemy_spec` 的
   硬编码读取，并为 18 个文件保留总节点数、边数、终点和关键点 parity 测试。
4. 在所有消费者切换并通过测试前保留旧 `enemy_spec.yaml` 只读对照；删除属于独立
   可回滚批次，不能与状态机重写混在一起。

### 2. 页面识别和动作门禁

1. 把 reset 按钮、决战舰队标题、use-last-fleet、二卡/三卡前进浮层所需模板和 ROI
   放到 `decisive_page/constants.py`/资源模块；坐标使用 `0.xxxx`，每项写业务语义。
2. 把“等待稳定、正向模板确认、OCR 输入/解析、地图像素签名”放入
   `decisive_page/recognition.py` 或现有 `overlay.py` 的对应职责，`page.py` 只组合页面动作。
3. 总览页 `reset_chapter()` 必须先确认当前页面和 reset 控件，再点击并确认结果；未知
   页面、按钮未命中或确认失败均 fail closed。
4. 决战准备页回退必须用决战地图 checker；普通地图 checker 不能作为兼容 fallback。
5. `wait_for_entry_phase()` 的阶段顺序建议为：船坞满、use-last-fleet、前进点浮层、
   战备舰队浮层、确认地图页。每一步只接受正向证据，超时返回可诊断错误。

### 3. 业务状态机和路线选择

1. 保留目标现有 `DecisivePhaseHandlers`、`DecisiveController` 和
   `ManualRepairRequiredError` 生命周期，先把“进图后等待/状态识别”替换为页面公开方法。
2. 前进卡片选择改为消费 `MapData.get_leftmost_choices()` 的结果；不能继续以固定
   `index=0` 代表所有地图，除非用户确认“左侧卡片永远等价于路线第一边”。
3. 当前目标状态只保存基础节点字母，而参考数据使用 `A1/A2` 等分支节点 ID。必须
   先取得用户对以下契约的确认：
   - 继续只保存基础字母，运行时每次以列/索引选择分支；或
   - 扩展状态、日志和恢复数据保存分支节点 ID。
4. 只有在分支状态契约确定后，才接入终点、关键点、敌方编成和下一节点选择；不要在
   数据迁移和状态模型决策之间加入临时映射或第二个 route cursor。
5. 进图、暂离、撤退、战备舰队获取、前进点和准备页回退分别增加状态序列测试，确保
   旧的 `0577f15` 2 秒稳定窗口不会被新轮询静默删除；如新轮询证明等价，再单独评估
   是否调整等待时长。

### 4. API、任务和配置适配

1. 决战请求仍由当前 `server.schemas.DecisiveRequest` 和 Processor 入口拥有；不要把
   参考 worktree 的旧 `TaskManager` 或 `ops` 参数直接复制。
2. 当前 `DecisiveConfig` 的 `chapter`、舰队、维修、解装和技能配置要与每个 EX 数据
   的边界分开：地图文件提供地图事实，用户配置提供运行策略。
3. 如果新增分支节点、卡片数量或恢复状态字段，必须同时更新 API/序列化/日志契约和
   所有消费者，并先取得用户确认；未改变外部契约时优先使用内部模型。

### 5. 回归与实机验证

1. 先跑数据契约和纯识别测试，再跑决战页面/业务 focused 测试。
2. 最小状态序列覆盖：新章节入口、已有进度 use-last-fleet、首进前进点、选择后地图、
   战备舰队浮层、准备页进入/回退、暂离恢复、撤退重置、船坞满和重置失败。
3. 通过离线截图后，再在设备上执行短链路；只有短链路稳定后才执行参考 worktree 的
   10 票稳定性长跑，记录每票暂离/撤退/远征收取和异常恢复。
4. 每个垂直切片执行目标 compileall、import smoke、focused pytest、目标文件
   pre-commit 和 `git diff --check`；实机未跑不得写成实机兼容。

  用 `get_leftmost_choices()` 的隐式猜测掩盖。

  做像素 parity 和模板来源记录，不能只复制数值。

- 参考新增 ADB DLL/EXE 和独立 E2E 工具包不属于决战运行时，除非另有任务授权，不纳入
  目标架构。
- 活动页误识别问题是独立视觉 TODO，不作为决战数据/状态机升级的隐式前置修复。
