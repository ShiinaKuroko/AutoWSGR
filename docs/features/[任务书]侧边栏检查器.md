## 1. 为什么 `sidebar/main_page` 是重写而不是追加

现有 `sidebar/main_page/page.py` 是旧实现：构造函数收 `UIContext`，import 了
`autowsgr.application.ui.navigation.interaction`（**该模块已随旧导航器删除**），现在连导入都过不去。
同时它依赖的 `autowsgr.common.types` 也已不存在。

因此本次按新框架重写：只收 `ContextHandle`，只提供点击方法，不做识别与流程编排
（识别归 checker，流程归导航器）。`constants.py` 里的坐标沿用并按红框校准。

## 4. 每个 checker 的语义

| checker | 前识别 | 后识别 |
| --- | --- | --- |
| `check_sidebar_page` | 侧边栏出现（`SIDEBAR_MAIN` 命中） | 侧边栏消失 |
| `check_build_page` | 建造二级菜单弹出 | 二级菜单消失 |
| `check_intensify_page` | 强化二级菜单弹出 | 二级菜单消失 |
| `check_friend_page` | 好友页面出现（「添加」页签命中） | 好友页面离开 |

四个入口统一签名 `(ctx, *, absent=False, attempts, interval_seconds)`，与其余 checker 一致；
前三个默认按导航确认节奏（5 次 / 1 秒），好友同样。

好友页面先只建 checker 与控制器，**好友业务功能仍为 TODO**。

## 7. 导航链路（用户 2026-10-12 定）

```text
主页 → 侧边栏 → 建造二级菜单 → 建造页面（建造 / 解装 / 开发 / 废弃）
建造页面 → 主页（经每日浮窗链）
主页 → 侧边栏 → 强化二级菜单 → 升级页面（强化 / 改造 / 技能）
升级页面 → 主页（经每日浮窗链）
主页 → 侧边栏 → 好友页面
好友页面 → 主页（经每日浮窗链）
侧边栏 → 主页（点空白处，不经浮窗链）
建造二级菜单 → 主页（与侧边栏点同一坐标，不经浮窗链）
强化二级菜单 → 主页（与侧边栏点同一坐标，不经浮窗链）
```

**回主页分两种走法，关键区别是要不要过每日浮窗链**：

| 起点 | 走法 |
| --- | --- |
| 侧边栏 / 建造二级菜单 / 强化二级菜单 | 点空白处收起，**直连主页面**。此时当天浮窗早已处理过，回程不会再弹 |
| 建造页面 / 升级页面 / 好友页面 | 点各页返回按钮，**经每日浮窗链**回主页面 |

前三条边共用同一落点 `CLICK_CLOSE = (0.5391, 0.5000)`（侧边栏只占左侧，中部是空的）。
