## 0. 目标与范围

把侧边栏域接进导航器：主页能点开侧边栏，侧边栏能展开建造 / 强化 / 进好友，三个页面都认得出。

**做**：

1. `home/main_page`：补侧边栏落点（`NAV_POSITIONS['sidebar']`，`Target.SIDEBAR` 已存在）；
2. `sidebar/main_page`：**按新框架重写**，提供「展开建造 / 展开强化 / 进入好友」三个方法；
3. 新建 `checker/sidebar/`（constants / recognition / checker）；
4. 注册 `SIDEBAR`、`BUILD`、`INTENSIFY` 到 `_PAGE_CHECKERS`。

**不做**：

- 好友页面（`FRIEND`）的 checker —— 好友功能是 TODO，本次好友只做「点条目 + 后识别侧边栏消失」；
- 建造、强化的业务流程（点建造、选配方等）。

## 1. 为什么 `sidebar/main_page` 是重写而不是追加

现有 `sidebar/main_page/page.py` 是旧实现：构造函数收 `UIContext`，import 了
`autowsgr.application.ui.navigation.interaction`（**该模块已随旧导航器删除**），现在连导入都过不去。
同时它依赖的 `autowsgr.common.types` 也已不存在。

因此本次按新框架重写：只收 `ContextHandle`，只提供点击方法，不做识别与流程编排
（识别归 checker，流程归导航器）。`constants.py` 里的坐标沿用并按红框校准。

## 4. 每个 checker 的语义

| checker | 前识别 | 后识别 |
| --- | --- | --- |
| `check_sidebar_page` | 侧边栏出现（`SIDEBAR_MAIN` 命中） | 侧边栏消失 |
| `check_build_page` | 建造二级菜单弹出 | 二级菜单消失 |
| `check_intensify_page` | 强化二级菜单弹出 | 二级菜单消失 |

三个入口统一签名 `(ctx, *, absent=False, attempts, interval_seconds)`，与其余 checker 一致。

**好友的到达确认**：本次不用 `FRIEND` 模板，改由「侧边栏消失」表达——点好友条目后侧边栏收起，
即离开 `SIDEBAR`。

## 5. 已知隐患

`SIDEBAR_MAIN_720P.png` 含 **`SALE` 限时标签**（「商城」条目右下角）。活动结束后标签消失，
模板会失效。**建议**后续把识别区域收窄到只含「商城」文字（约 `(40,35)-(200,78)`）；
本次先按用户给的红框实现。
