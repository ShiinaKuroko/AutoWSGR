# 战斗域游戏结构 — 征战页与编队准备页通用规则

> 来源: 用户实测梳理 (2026-08-24)。战斗域统一 Runner 设计的核心输入。
> 硬约束: 以下规则是游戏机制, 不是代码实现选择, 实现必须服从。

## 一、征战页 (MAP) 结构

```
出征 (首页点击跳转到新页面)
├── 退出 ◁
├── 普通出征 (面板)
├── 演习     (面板)
├── 远征     (面板)
├── 战役     (面板)
└── 决战     (面板)
```

**关键事实**:

1. 五个模式是**同一个页面的五个面板** (tab 切换, 不换页)。
2. 退出按钮坐标**通用**: 普通出征、演习、远征、战役共用同一坐标。
3. 决战的退出按钮坐标相同, 但**交互逻辑不同** (需单独处理)。
4. **回主页锚点**: 除决战外, 只要未进入战斗, 任何时候都可通过退出按钮
   退回上一级 → 最终回主页。这满足"每个打断点必须能回主页"的调度契约,
   对应导航图现有的 `MAP → MAIN` 单边, 无需每面板建边。

## 二、舰队准备页 (BATTLE_PREP) 编队规则

准备页本身也是五模式通用的, 差异全在编队方式:

| 模式 | 编队方式 | 可选队伍 | 1号位必须非空 |
|------|---------|---------|--------------|
| 普通出征 | 选队 | 1-4 | ✓ |
| 演习 | 选队 | 1-4 | ✓ |
| 远征 | 选队 | **5-8** | ✓ |
| 战役 | 逐框填船 (萝卜一个坑) | 不可选队 | **✗ (唯一例外)** |
| 决战 | 逐框填船 (萝卜一个坑) | 不可选队 | ✓ |

**关键事实**:

1. **选队模式** vs **填船模式** 是两种根本不同的编队交互:
   - 选队: 点击队伍编号切换 1-4 / 5-8 队。
   - 填船: 无队伍概念, 每个槽位逐个指定舰船 (战役/决战)。
2. 战役是**唯一**允许 1 号位为空的模式; 其余所有编队页 1 号位必须非空,
   否则无法出征。
3. **左对齐填充机制**: 在 6 号位添加船只时, 游戏会自动向左滑动补齐空位。
   即: 实际占用的槽位永远左对齐, 物理框位 ≠ 逻辑槽位。
   - 代码侧的槽位状态跟踪必须模拟这个左移 (与决战换船逻辑中的
     内存槽位左移是同一游戏机制): 删除中间船后, 后续船只左移,
     尾部变空, 不能按物理框位死记。

## 三、对架构的映射 (设计输入)

统一战斗 Runner 的画像数据 (FleetPolicy):

```python
NORMAL     = FleetPolicy(select=True,  fleets=(1, 2, 3, 4))
EXERCISE   = FleetPolicy(select=True,  fleets=(1, 2, 3, 4))
EXPEDITION = FleetPolicy(select=True,  fleets=(5, 6, 7, 8))
CAMPAIGN   = FleetPolicy(select=False, require_slot1=False)  # 唯一例外
DECISIVE   = FleetPolicy(select=False, require_slot1=True)
```

- 远征业务属后勤域, 但其编队交互引用战斗域的同一 FleetPolicy。
- 决战的例外 (退出交互/填船) 在画像中各有落点, 禁止 if-decisive 散弹枪。
- 左对齐机制 → 填船模式的槽位状态建模必须以"逻辑占用序列"为准。

## 四、YAML 驱动的执行流程 (统一骨架)

四类战斗 (普通出征/演习/战役/决战) 全部由 YAML 驱动, 流程固定为:

```
1、识别 YAML 数据 → 确认链路 (哪个模式、什么参数)
2、组装步骤      → 步骤 = 可打断节点 (插入任务时, 出征中的战斗不可打断,
                   只能等打完; 步骤边界 = 调度器的打断点)
3、执行          → 骨架逐步执行, 每步终态可回主页
4、编队 → 出征    → 按类型查 FleetPolicy, 公用同一套编队框架
```

**打断点语义** (用户明确强调):
- "进入出征就要等打完了" — 战斗内 (run_combat 期间) 不可打断。
- 可打断点只存在于组装后的**步骤边界**: 切面板后、选目标后、编队后、
  下一场开始前。每个打断点满足"能回主页"契约 (征战页退出按钮)。

**步骤序列** (五阶段骨架, 模式差异全部压缩在 ②):

| 阶段 | 普通出征 | 演习 | 战役 | 决战 |
|------|---------|------|------|------|
| ① 切面板 | 出征 tab | 演习 tab | 战役 tab | 决战 tab |
| ② 选目标 | 选地图 | 识别对手→挑战→二次弹窗挑战 | 选难度→选战役 | (独立处理) |
| ③ 编队 | 选队 1-4 | 选队 1-4 | 逐框填船 | 逐框填船 |
| ④ 点右下角出征 | ✓ | ✓ | ✓ | ✓ |
| ⑤ run_combat | 引擎统一 | 引擎统一 | 引擎统一 | 引擎统一 |

①③④⑤ 全通用; ② 是"面板上若干次点击/识别直到到达准备页"的同形步骤序列,
由画像 (CombatProfile) 描述; 编队阶段按 FleetPolicy 查表公用一套编队框架。
