# 推图活动 ROI 与点击坐标

来源截图：`debug/nav/event/推图活动roi裁切模板/`（1280x720，图上红框为用户标注）。
基准分辨率 **1280x720**；归一化坐标 = 像素 / (1280, 720)，按项目约定与 `point()` / `points()` 的输入一致。

> 取框方法：先用红色遮罩的「满行 / 满列红色占比 > 0.7」定位红框描边，再取描边**内框**。
> 不要按外框统一内缩——卡面美术本身含红色，会把外框撑大，导致描边残留。

## 2. 关卡位置坐标

来源：`关卡坐标点击.png`，图上 6 个红框（细描边约 2px）标出 6 个关卡节点。下表「框」为红框外接矩形，点击点取框中心。

| EX12 | 962,497,100,82 | 0.79063,0.74722 | 1012, 538 |

编号顺序 = **从上到下的行、每行内从左往右**（EX7/EX8/EX9 是同一排，EX10/EX11/EX12 各自一排）。
该编号已由用户在图上标注确认（EX7 左上 / EX8 上中 / EX9 右上 / EX10 中左 / EX11 中 / EX12 右下）。

普通模式与困难模式**共用这 6 个位置**：普通模式 = EX1…EX6，困难模式 = EX7…EX12，同一格编号相差 6。已在 `困难地图.png` 与 `普通地图.png` 上叠点验证：6 个点分别落在两张图的 6 个关卡图标上，两张图布局完全一致，仅配色不同。

> 换活动地图或换分辨率需重新取点。

## 3. 裁剪命令

```bash
python tools/debug_toolkit/main.py roi --image <源图> --roi x1,y1,x2,y2
```

输出到 `tools/debug_toolkit/result/screenshot/<图名>/{1x,2x,4x,8x}/`。

注意事项：

- `roi.py` 原用 `cv2.imread` 读不了中文路径，已改为 `cv2.imdecode(np.fromfile(...))`。
- `main.py` 目前因 `annotate.py` / `collect.py` / `screenshot.py` 仍导入已被移除的 `autowsgr.common.device.adb` 而无法启动；
  在设备迁移补齐前，需直接调用 `tools.debug_toolkit.function.roi.run`。
