## 0. 本批目标（两件事一起做）

1. **`common.vision` 提供模板匹配中心坐标**：模板匹配结果自带中心，调用方不再各自手算；
2. **重写 `autowsgr/application/ui/controller/home/event_page`**（活动页面控制器）：把**识别**交回
   导航器的 `event_checker.stage_push`，控制器只保留**页面控制**：单次点击 + 回退/前进/切难度的导航动作。

### 0.1 `common.vision` 中心坐标

| 项 | 决定 |
| --- | --- |
| 载体 | 模板匹配结果（`TemplateMatchResult`）新增中心 |

| 归一化基准 | 当前截图的像素尺寸（3.0 的截图与模板统一 720P，即 1280x720） |

改造后，以下落点改为**用匹配产出的中心**，不再写死坐标：

- 难度切换按钮（每期活动位置可能不同，写死会随活动漂移）；
- "确认出征"按钮（浮窗位置随节点变化）。

仍然写死坐标的（位置固定、不需要识别）：章节入口六个落点、关浮窗、返回首页。

## 1. 边界（用户已定）

1. UI 控制器只持有**页面控制**相关内容和**它自己用得到的少量识别**；页面识别归导航器 checker。
2. 活动控制器只有两类能力：**读章节入口并点击**、**读浮窗坐标并点击**。
3. 控制器按 **event type** 分类，与 `event_checker` 同构。
4. 控制器提供**稳定入口 + 私有方法**，垂直调用 `common`。
5. 入口额外为导航器提供：**回退到上一级**、**前进到某个页面**。
6. **前后识别（等待与确认）由导航器负责**，控制器只做**单次点击**，不 import checker、不等页面。

## 2. 目标结构

```text
autowsgr/application/ui/controller/home/event_page/
├── __init__.py            # 稳定入口：按 event_type 暴露控制器
├── page.py                # EventPage：四个公开入口 + 私有查找/校验/点击
├── constants.py           # 跨玩法共用坐标（返回首页）
└── stage_push/                # 普通推图玩法，与 event_checker/stage_push 同构
    ├── __init__.py
    └── constants.py       # 本玩法点击坐标：章节入口、确认出征、失败浮窗关闭等
```

不建 `operations.py`：本模块只有"点一次"这一个原子操作，直接
`ctx.runtime.ctrl.click(x, y)`（垂直调 `common.device.service`）。

## 3. 公开面

| 入口 | 语义 | 实现 |
| --- | --- | --- |
| `go_to_overlay(ctx, stage)` | 前进到章节浮窗：点该章节入口 | 解析 `stage` → 查 `STAGE_POSITIONS`（EX1–6 与 EX7–12 共用同一组六个落点）→ 点击 |
| `go_to_prepare(ctx, position)` | 从浮窗前进到通用编队页：点"确认出征" | `position` 来自 checker 匹配出的中心 → 点击 |
| `go_back(ctx)` | 从活动地图回退到首页 | 用 `CLICK_HOME_BACK = (0.0329, 0.0570)` → 点击 |
| `switch_difficulty(ctx, position)` | 切换普通/困难模式 | `position` 来自 checker 匹配出的难度按钮中心 → 点击 |
| `click_overlay_close(ctx)` | 关闭章节浮窗（= 从浮窗回退到地图） | `CLICK_OVERLAY_CLOSE = (0.9532, 0.1048)` → 点击 |

坐标来源说明：

- `CLICK_OVERLAY_CLOSE` 由用户标注截图量取（标注图 1154x649，红框中心 (1100, 68) →
  1280x720 的 (1220.1, 75.4) → 归一化四位小数 `0.9532, 0.1048`）；
- `CLICK_HOME_BACK` 由用户标注截图量取（标注图 1154x649，红框中心 (38, 37) → 1280x720 的
  (42.2, 41.1) → 归一化 `0.0329, 0.0570`）；旧值 `0.0274, 0.0556` 换算后是 (35.1, 40.0)，两者相差约
  7 像素、同属按钮范围，按新标注为准；
- `switch_difficulty` 与 `go_to_prepare` 的落点由**识别产出的中心**给出（见 §0.1）：
  导航器先让 checker 匹配难度按钮 / 确认出征按钮，把中心坐标传给控制器点击；
- 控制器因此不需要持有这两个落点常量，也不会随活动漂移。

**章节入参兼容**：控制器接受旧格式 `E1`–`E6`（= EX1–EX6）与 `H1`–`H6`（= EX7–EX12），
在 `_resolve_stage_position` 内部转换成章节编号再查落点表；对外不急切换新格式。

- **章节入口与浮窗坐标是固定坐标**（查表）；模板 ROI 的中心只用于"确认出征"这一个落点，
  值与 `event_checker.stage_push.constants.SORTIE_PREPARE_ROI` 的中心一致，两份各自持有并在注释里互相指明。
- 私有方法：`_resolve_stage_position(stage)`、`_resolve_overlay_position(action)`、`_click(position)`。

## 6. 与导航器的编排关系

```text
导航器
  ├─→ event_checker.stage_push.read_xxx(ctx)          # 识别事实
  ├─→ event_page.EventPage.go_to_overlay(ctx, stage)   # 单次点击
  ├─→ event_checker.stage_push.read_xxx(ctx)          # 确认（expect_* 由导航器决定）
  ├─→ event_page.EventPage.go_to_prepare(ctx)
  └─→ event_page.EventPage.go_back(ctx)
```

控制器不 import checker、不 sleep 等页面、不做重试：等待与重试都是导航器的 `expect_*`。
