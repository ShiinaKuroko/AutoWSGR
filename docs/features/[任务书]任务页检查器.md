## 3. 页面与边

| `PageName` | 画面 | 到达确认 |
| --- | --- | --- |
| `MISSION`（已有） | 任务页 | 「全部」页签激活 |
| `MISSION_REWARD_CONFIRM`（新增） | 「获得」浮窗 | 「确认」按钮出现 |

四条边：

```text
主页面 → 任务页          点「任务」按钮，到达确认真确认
任务页 → 主页面          点返回，经每日浮窗链，confirm=False（进链的边）
任务页 → 获得浮窗        「全部领取」在就点，confirm=False（有按钮没按钮都算到了）
获得浮窗 → 任务页        点「确认」，真确认
```

与每日浮窗链同构：**进链的边 `confirm=False`，链尾才真确认。**

## 4. 游戏内点击逻辑（用户描述）

```text
主页点「任务」→ 进入任务页
  ├─ 有未领取的奖励：右下角出现「全部领取」
  │    点它 → 弹出「获得」浮窗 → 点「确认」→ 浮窗消失，回到任务页
  └─ 奖励都领完了：没有「全部领取」，直接点返回
```

**「全部领取」按钮不遮挡任务页**，所以它不是独立页面，按「先问再做」处理：
`read_claim_all_visible` 判断在不在，在就点。

**有浮窗时「全部」页签的置信度很高**：浮窗弹出后任务页仍在背后，页签可见。
