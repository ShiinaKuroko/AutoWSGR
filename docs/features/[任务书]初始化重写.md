## 0. 目标与范围

把「启动游戏 → 登录 → 主页 → 清浮层」整条链路重写，归属 dispatch，并删掉旧实现。

**做**：新增 `autowsgr/dispatch/startup.py`；启动链路按新导航器重写；区服选择接入；
调用方切到新入口；删除 `application/runtime/startup.py` 与 `application/runtime/initialize/`。

**不做**：业务执行器自身的其余改造；`launcher.py` 改名；GUI 侧适配。

## 1. 模块归属（用户 2026-10-11 定）

| 职责 | 归属 |
| --- | --- |
| 进程 bootstrap：配置加载、日志初始化、连接设备、构造 RuntimeContext | 留在 `application/runtime/launcher.py`，**名字不改** |
| 游戏启动与幂等初始化 | 新增 `autowsgr/dispatch/startup.py` |
| 何时启动程序、何时 SL | **dispatch 处理器决定并调用**；业务执行器只上报问题，不自己触发 |

理由：四层级是 `dispatch 处理器 → 业务执行器 → 导航器 → common`，启动流程不属于任何业务，
是纯编排；`dispatch/session.py` 与 `dispatch/context/` 已经在这一层，启动流程与它们同层。

## 2. 旧流程盘点（业务链路保留，代码重写）

旧实现散在三处、两份重叠：

```text
[launcher] 配置 → 日志 → 连设备 → 造 RuntimeContext
    └→ startup.ensure_game_ready()          398 行

[dispatch.processor / business.bettle.executor]
    └→ initialize.initialize()              362 行（含 overlays / updater）
```

### 2.1 `initialize`：执行器的永远第一步

```text
1. 取包名（配置 account.game_app）
2. 游戏没运行 → 启动流程：start_app → 等「点击进入」（≤120s）
     → updater.needs_update（空实现）→ 点「进入游戏」→ 等主页（≤30s）
3. goto_page(HOME)（≤20s 重试）
4. 失败 → SL 强杀 + 冷启动（只试 1 次）→ 再 goto_page(HOME)
5. 仍失败 → RuntimeError
```

### 2.2 `startup.ensure_game_ready`：launcher 调用

```text
1. 游戏没运行 → start_game → wait_for_game_ui（启动画面 / 登录浮层 / 任意已知页面，任一即算就绪）
   游戏在运行 → identify_current_page 认得出就返回；认不出就 goto_page(HOME) 重试 20s，仍不行就重启
2. handle_daily_overlays（日期门控）
```

### 2.3 两份的差异

| 点 | `initialize` | `startup` |
| --- | --- | --- |
| 主页判定 | 新 `check_home_page` | 旧 `HomePage.check_current_page(screen)` |
| UI 就绪判定 | 严格：必须等到「点击进入」 | 宽松：启动画面 / 浮层 / 任意页面都算 |
| 更新检查 | 有调用（空实现） | 只有 TODO |
| 每日浮层 | `overlays.py`（任务级 `OverlayState` 日期门控） | `handle_daily_overlays`（挂在 RuntimeContext） |
| SL 兜底 | 有（重启一次） | 有（在 recover 里） |

结论：以 `initialize` 的业务契约为准；`startup` 的宽松判定丢弃。

### 2.4 必须保留的业务契约

| 契约 | 内容 |
| --- | --- |
| 幂等 | 任意状态进来，出去必定是「主页 + 浮层已清 + 待机」；SL 与异常恢复复用 |
| SL 只重启一次 | 防死循环，仍失败交处理器 |
| 浮层先标记再执行 | 即使本次消除中途失败，当天也不再重试，避免异常画面死循环 |

### 2.5 必须保留的业务参数

| 参数 | 旧值 |
| --- | --- |
| 等待「点击进入」 | 120s，1s 轮询 |
| 点进入后等主页 | 30s |
| 恢复主页面超时 | 20s，1s 重试 |
| 强杀后等待进程退出 | 2s |
| 浮层消除上限 | 5 次，每次间隔 1.5s |
| 确认弹窗兜底 | 3s |

### 2.6 丢弃的部分

- `updater.py` 空实现 → 被「更新提示 → 报错」取代；
- `startup.wait_for_game_ui` 的宽松判定（识别到任意已知页面就算就绪）；
- 两套浮层实现合并成导航器的每日弹窗前置流程（进程级）；
- 业务执行器自己调 initialize 的写法。

## 3. 新链路设计

### 3.1 公开入口

```python
# autowsgr/dispatch/startup.py
def ensure_ready(ctx: ContextHandle) -> None:
    """执行器的永远第一步：任意状态 → 主页 + 浮层已清。幂等。"""
```

### 3.2 主流程

```text
ensure_ready(ctx):
  ① 游戏没运行 → _launch_game(ctx)
  ② NavigationService(ctx).navigate_to(PageName.HOME)
       导航器自己短路已在主页的情况；经过首页时跑每日弹窗前置流程
  ③ 失败 → _restart_game(ctx)（SL，只一次）→ 再 navigate_to(HOME)
  ④ 仍失败 → 抛错，由 dispatch 处理器决定后续（上报 / 停止）

_launch_game(ctx):
  ① 取包名（配置 account.game_app）→ start_app
  ② 前识别「健康游戏提示」出现（≤120s）
  ③ 后识别「健康游戏提示」消失
  ④ 分支一 · 更新：
       后识别「需要更新」通过 → 没有更新，进入分支二；
       前识别「需要更新」通过 → 抛 ManualRepairRequiredError（交用户手动处理）
  ⑤ 分支二 · 加载：
       后识别「正在进入港区」通过 → 加载结束，进入下一步；
       前识别通过 → 仍在加载 → 等 3s，再做一次后识别
  ⑥ 前识别「登录页」（进入游戏模板与换区入口模板二选一）
  ⑦ _select_server(ctx)（见 §4）
  ⑧ 点「进入游戏」→ 后识别「进入游戏」模板消失
  ⑨ 回到 ensure_ready ② 确认主页
```

术语：前识别 = `expect_*`（识别存在），后识别 = `expect_*_absent`（识别不存在）；
分支顺序按用户 2026-10-11 定稿的「先后识别、再前识别」。

### 3.3 与旧流程的对应

| 旧步骤 | 新步骤 | 变化 |
| --- | --- | --- |
| 等「点击进入」 | 前 + 后识别「健康游戏提示」 | 增加"确认已切走" |
| `updater`（空实现） | 前后识别「需要更新」+ 报错 | 由空实现变成明确报错 |
| `wait_for_game_ui` 一刀切 | 前后识别「正在进入港区」+ 3s 重试 | 判定收紧 |
| 无 | 区服选择 | 新增 |
| 点「进入游戏」 | 点「进入游戏」+ 后识别确认 | 增加终态确认 |

## 4. 区服选择（用户 2026-10-11 定）

### 4.1 用户设置

提供「默认 + 四个区服」：默认 = 不处理换区；四个区服 = 胡德 / 俾斯麦 / 昆西 / 长春。

建议落点（待确认）：

```yaml
account:
  game_app: 官服
  server: 默认            # 默认 / 胡德 / 俾斯麦 / 昆西 / 长春
```

类型用 `StrEnum`（与 `GameAPP` 一致的写法），放 `application/runtime/types.py`：

```python
class LoginServer(StrEnum):
    """登录时选择的区服；default 表示不处理换区。"""

    default = '默认'
    hood = '胡德'
    bismarck = '俾斯麦'
    quincy = '昆西'
    changchun = '长春'
```

### 4.2 运行期状态

区服选择状态是**进程级**，放 `dispatch/session.py` 的 `SessionState`：

- 程序启动时为空 → 按用户设置选择一次；
- 程序运行中 SL 不再选择（上下文已有）；
- **程序重启后重新选择**（进程级状态随进程消失）。

### 4.3 换区流程

```text
_select_server(ctx):
  若 session.server_selected → 返回（本次运行已选过）
  若用户设置为「默认」→ 标记已选，返回
  index = login_checker.find_server_position(ctx, 用户设置区服)
  index 为空 → 按找不到处理（报错或跳过，见待定）
  ① 点「点击换区」→ 后识别「进入游戏」模板消失（区服列表已展开）
  ② 点对应区服条目 → 后识别「切换大区」模板消失（回到登录页）
  ③ 标记 session.server_selected
```
