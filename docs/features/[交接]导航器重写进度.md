## 6. 已确认的技术约定

### 6.1 导航器

- 调用方向**单向**：导航器 → 控制器，控制器不反向依赖导航器；
- **可达列表放一个文件**（`navigation/registry.py`），每条边一行数据（lambda），**不为边写转发函数**；
- **确认由 checker 决定**：导航器的确认表统一收 `(ctx) -> bool`，不把判断标准漏到导航器；
- `navigate_to(target, **params)` + `navigate_back()`（不用 `fall_back`，那是"退而求其次"的意思）；
- 路径用"广度拼接"（`get_targets(当前页)` 拿下一跳）；
- 失败**直接抛**，由处理器决定（遍历所有 checker 定位当前页，全找不到就重启 app）；
- 经过首页时才跑每日弹窗前置流程（公告与奖励**两段解耦**，各自检测）。

### 6.2 识别

- 前后识别都**先截图再识别**，截图由识别入口自己截（`expect_*` 每轮重试都截图并缓存）；
- "前识别" = `expect_*`（确认存在），"后识别" = `expect_*_absent`（确认不存在）；
- 启动流程的分支顺序是**先后识别、再前识别**（先确认不存在，再确认存在）；
- OCR 基本都是单行文字，调用时传 `recognition_profile='single_line'`；
- `common.vision` **没有"只读文本"的公开入口**（只有带期望的 `expect_ocr`）；
  区服定位用"目标名对四条 ROI 各问一次真假"，不新增 common 能力。

### 6.3 坐标与资产

- 坐标一律归一化 `[0,1]`，四位小数；左/上取 floor、右/下取 ceil；
- 模板目录小写、文件名全大写，形如 `{PAGE}_{PURPOSE}_{RESOLUTION}.png`；
- 生产模板放 `resources/image/application/ui/navigation/page_checker/<模块>/`，
  `C:\ShiinaKuroko\01.Project\debug\nav\` 下只是静态验证样本，不是生产资源；
- 量坐标的办法：从标注图里找纯红框（`r>180, g<80, b<80` + 填充率 <0.6 过滤实心红色），
  再去**干净截图**里按同一个框裁模板。
