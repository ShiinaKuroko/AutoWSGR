# Sakuya 战役架构与 E2E 任务书

任务日期：2026-08-31
任务分支：`codex/20260830-sakuya-exercise-consolidated-7a6c`
任务范围：AutoWSGR 后端战役链路、编队基建、日志和断点验证。
当前状态：`in_progress`

## 一、架构修正

- 复查全仓，不只关注演习链路。
- 执行器直接使用共享 Navigator 能力，不再为 `goto` 重复包一层。
- 共享 Navigator 需要有统一入口由业务层业务调用，在入口挂载具体实现方法，实现垂直架构
- 选船模块提供统一入口；识别、选船和 OCR 实现下沉到 application，业务层只提供规则。
- 所有日志统一为 `[Module] message`，所有的模块均采用统一的英文模块+中文信息的格式
- 注释使用短句说明真实行为、边界和原因，参考已调整的演习执行器注释风格。
- `task_type` 必须随战役和演习上下文传入编队模块；普通战斗、活动战斗、演习继续使用已有通用编队逻辑。
- 业务上下文必须在任务周期内持久化，以支撑暂停后恢复任务
- 战役支援开关不属于战役业务模块，应迁移到战斗引擎公共能力，注释固定为：
  `确保军阶战役支援开关处于目标状态。`

## 二、战役业务流程

1. Processor 将指令交给战役业务，业务读取并校验 YAML。
2. YAML 校验通过后保存 `task_type`。
3. 通过共享 Navigator统一入口调用方法导航到战役入口。
4. 初始化运行时上下文。
5. 读取战役模式（普通/困难）、章节（驱逐/巡洋/战列/航母/潜艇）和编队信息。
   编队为空时沿用当前队伍。
6. 编队支持两种输入：
   - 后端完整写法：包含完整 `name` 和 `ships`；测试使用此写法。
   - GUI 连接写法：只有一个队伍 `name`，例如 `4日驱周常队`。
7. 连接写法根据名称查找队伍 YAML。队伍文件可能位于用户个人配置目录或系统预设目录，
   例如：`AutoWSGR-GUI/resource/system_team_plans/team-4德驱周常队.yaml`。
   GUI 与后端的路径契约留作最终集成 TODO，不在本批猜测。
8. 识别当前战役模式，不符合时点击切换；符合后点击进入目标章节。
9. 进入编队页时把 `task_type='campaign'` 传给选船模块，执行战役专用编队。
10. 返回执行器调用统一战斗引擎，等待战斗结束并记录战役次数。
11. 是否继续下一次由 Processor 决定：连续战役可复用战役页面；插队任务开始前回到主页锚点。

## 三、战役编队契约

- 每次执行带有明确编队配置的战役任务，先清空当前六个物理槽位，再执行编队。
- 一号位不能为空。
- 战役槽位是固定物理槽位；删除槽位后不发生左移，`123456` 删除 1 后保持为
  `None23456`。
- 战役不能拖动卡片，只能点击目标槽位进行点对点更换或清空。
- 普通战役无舰种限制，允许只编 1 艘舰船。
- 困难战役要求每个可用槽位都有舰船，并按章节固定舰种：
  - 驱逐：驱逐、驱逐、驱逐、驱逐、驱逐、驱逐
  - 巡洋：战列、重巡、重巡、轻巡、轻巡、驱逐
  - 战列：战巡、战列、重巡、重巡、驱逐、驱逐
  - 航母：航母、航母、驱逐、驱逐、驱逐、驱逐
  - 潜艇：潜艇、潜艇、潜艇，编队数量为 3
- 驱逐困难战役因舰种由游戏规则限定，可覆盖 OCR 的舰种检测，只严格校验舰名和等级。
- 普通战斗、活动战斗、演习不切换到战役分支，继续使用已有通用换船和 OCR 逻辑。

## 四、战役断点与上下文

检查以下断点是否可暂停、保存任务上下文并安全回主页：

1. 导航到战役入口后。
2. 进入编队页面后。
3. 任意一个位置换船结束后。
4. 最后一个位置换船结束、进入战斗前。
5. 战斗结束后、下一次战役或插队任务开始前。

换船流程分为“点选目标舰船”和“位置调整”两个动作；战役只保留点选动作，通用编队的拖动动作
需要单独评估上下文风险后再加断点。每个断点都要保存可恢复的任务进度和已完成槽位。

## 五、日志契约

统一使用 `[Campaign]` 模块前缀，至少输出：

- `[Campaign] 开始战役任务`
- `[Campaign] 战役战斗开始`
- `[Campaign] 战役队伍加载：使用队伍 {fleet_id}、编队配置加载成功`
- `[Campaign] 战役队伍加载：使用队伍 {fleet_id}、未配置编队，沿用当前队伍`
- `[Campaign] 进入战斗：阵型配置={}，夜战配置={}`
- `[Campaign] 战斗结束，战役结果: {}，已执行战役次数 X，剩余次数 X`

OCR 的名称、等级严格校验日志沿用选船模块的统一格式；日志标点在全链路内保持一致。

## 七、E2E 验收用例

1. 覆盖全部战役断点。当天 00:00 后允许插入演习任务（次数为一次）；演习次数耗尽后再依次插入远征检查和奖励收取，
   不在每个断点重复插入同一任务。
2. 验证换船流程，允许组合本任务的驱逐队伍和演习队伍验证普通战役。
3. 验证战役编队禁止拖动、只允许点对点更换。
4. 验证普通战役无舰种限制且一艘舰船可执行。
5. 验证困难战役固定槽位舰种、数量和非空约束。
6. 每次执行配置明确的战役任务前先清空队伍，再执行目标编队。
7. 每个 E2E 从初始化开始并进入首页待机，结束回到首页；游戏进程异常退出时重新初始化。
