## 〇、分辨率基准审计与 1280x720 统一

### 关键结论：相对坐标天然分辨率无关，无需数值转换

代码中的坐标**除两组扫描区外全部是相对坐标 (0-1)**。960x540 与 1280x720 同为 16:9，
相对坐标在两个分辨率下指向同一物理位置——**"960x540 校准"的相对坐标在 1280x720 实机上
不会错位**。此前清单里"分辨率基准混用"问题经审计澄清：混用只存在于**推导注释**（旧代码
绝对像素），不影响运行正确性。运行时保障机制：

| 机制 | 位置 | 说明 |
|------|------|------|
| 相对点击 | ctrl.click(x, y) | 按实际截图尺寸换算绝对像素 |
| ROI 归一化 | vision/roi.py `to_absolute(w, h)` | 相对 → 任意分辨率 |
| 模板动态缩放 | image_matcher.py:64 `_scale_template_if_needed` | 540p 模板自动适配任意分辨率截图 |

### 真正分辨率绑定的项（全代码库仅此清单）

| 项 | 位置 | 基准 | 处理 |
|----|------|------|------|
| `_SCAN_AREA_EXERCISE` ×6 | combat/recognition.py:35-42 | 960x540 绝对像素 | **已转换 ×4/3**（见下表） |
| `_SCAN_AREA_FIGHT` ×6 | combat/recognition.py:45-52 | 960x540 绝对像素 | **已转换 ×4/3**（见下表） |
| `_SHIP_TYPE_CROP_OFFSETS` | choose_ship_page.py:69 | 1280x720 绝对像素 | ✅ 已是目标基准（运行时按 w/1280 缩放） |
| 敌舰识别 resize | combat/recognition.py:140 | 截图 resize 到 960x540 | 与扫描区配套，统一时一起改 1280x720 |
| 活动页模板匹配 resize | event/event_page.py:90 | 截图 resize 到 960x540 | 540p 模板配套，可保留或统一 |
| DLL 地图识别 | vision/api_dll.py:8 `_TARGET_H=720` | 720p | ✅ 已是 |

注意：`_SCAN_AREA_*` 当前与"截图 resize 到 960x540"管线**自洽**（先缩放截图再用 960x540

两处必须**同时改**。

### 校准基准审计（按推导来源）

**已是 1280x720 基准（无需动）**：
- 选船页：`_SHIP_TYPE_CROP_OFFSETS`、`_CARD_REFERENCE_WIDTH=1280`（运行时按实际宽度缩放）
- 出征准备页：`SHIP_LEVEL_CROP`/`SHIP_TYPE_CROP`（docstring 注明 1280x720 实机校准）
- 决战磁盘购买：`CLICK_BUY_TICKET_OPEN = (458*0.75/960, 665*0.75/540)` ≡ (458, 665)@1280x720
- 决战三种浮层模板（FLEET_ACQUISITION/CONFIRM_EXIT/ADVANCE_CHOICE，1280x720 实机采集）
- DLL 地图识别目标高度 720

**960x540 基准（相对值有效无需改，仅注释推导）**：
- 其余全部页面坐标。典型推导式 `(937/960, 277/540)`、`(36/960, 33/540)`、旧代码 (90, 206) 等

### YAML 存储格式（统一 1280x720 绝对整数）

```yaml
# 坐标一律为 1280x720 绝对像素，加载器归一化 (x/1280, y/720)
common:
  back: [28, 42]        # 相对 (0.022, 0.058)
```

转换规则：
- 960x540 绝对 → 1280x720 绝对：**×4/3**
- 相对坐标 → 1280x720 绝对：**x×1280，y×720**

### 新增信息：color 字段

本轮抓取首次附带每个坐标的**参考颜色 (RGB)**。用途：
- 点击前验证按钮存在（采样该点颜色与 color 比对）

- tolerance 均为抓取原值 0，实际颜色匹配需容差（建议 30-50），实机调试时校准
